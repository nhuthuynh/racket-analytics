# C4-CA decisions

Per-ticket decision file (PO rule 2026-10-07). Ticket: optional `extra_ca` build secret in `infra/compose.yaml` (VR3-S3-01). Context: platform/infra.

| Date | Who | Decision | Evidence | Why |
|---|---|---|---|---|
| 2026-10-17 | sre-devops-engineer | **Off by default through the secret id, not the secret file.** Every build service gets `secrets: [{source: extra_ca_file, target: "${EXTRA_CA_FILE:+extra_ca}"}]`; the top-level `extra_ca_file` reads `${EXTRA_CA_FILE:-/dev/null}`. Unset, the empty target falls back to the source name `extra_ca_file`, which no Dockerfile mounts | Probe builds (scratchpad, Compose v5.3.1): a top-level secret always mounts, even empty (`file: /dev/null` or `environment:` → `/run/secrets/extra_ca` 0 bytes); `file: ${EXTRA_CA_FILE:-}` → `read .../ca: is a directory`; a missing file → `failed to stat`; `target: ""` → id = source | An always-mounted empty `extra_ca` would make `[ -f /run/secrets/extra_ca ]` true and point `PIP_CERT`/`SSL_CERT_FILE` at an empty file (the default build would break); this keeps the default build's steps and secrets unchanged |
| 2026-10-17 | sre-devops-engineer | **Dockerfiles unchanged.** They already mount `extra_ca` with `required=false` in every networked `RUN` (QA-R2-03) and point `PIP_CERT`/`SSL_CERT_FILE`/`NODE_EXTRA_CA_CERTS`/`cafile=` at the mount | `test_no_dockerfile_requires_extra_ca_or_copies_it_into_a_layer` (both Dockerfiles) passes on `origin/main` | Changing the `RUN` lines would invalidate every developer's build cache for no behaviour change. `PIP_CERT` and `SSL_CERT_FILE` replace the trust store rather than append, so the README asks for the proxy's CA **bundle** (as `/root/.ccr/ca-bundle.crt` is) |
| 2026-10-17 | sre-devops-engineer | **Flow-style `secrets:` lines, no YAML anchor** | `test_compose.py::test_compose_file_contains_no_literal_secrets` failed on `secrets: *extra-ca-build-secret` and the block-style top-level `secrets:` | That existing test (not edited) wants every `*SECRET*:` line to hold a `${...}`; the flow form does |
| 2026-10-17 | sre-devops-engineer | **IT-04-14 builds a busybox probe through the real compose wiring (only `migrate`'s context/Dockerfile overridden), with `--no-cache`** | First green attempt: the CA build reported `none` from a cached step | BuildKit does not key its cache on secret contents; a real backend/web build is too slow for the 10-min `infra-tests` job, so it is the live evidence in the PR instead |
