| 2026-10-08 | senior-frontend-engineer (CI-WEBKIT-PD-R3S2-02) | **Cause of the WebKit-only failure of `fe-minors.spec.ts:24` (PD-R3S2-02): the spec routes `/api/matches/{id}/corrections` with `page.route` but does not block service workers.** `public/sw.js` has a `fetch` handler and calls `clients.claim()`, and `receivedMatch` signs in through pages first, so by `page.goto('/matches/{id}/sheet')` the page is controlled; in WebKit its fetches then go through the worker and Playwright's route never sees them (Chromium routes them anyway). Not a product defect: the worker passes `/api/*` to the network untouched (`tests/unit/service-worker.test.ts`) and the history is read only by `ScoreSheetView` → `api.corrections` (no other request or cache). **Fix:** (1) on `main`, a guard (`web/e2e/helpers/route-isolation.ts`, bound by `tests/features/e2e_route_isolation.feature` in Vitest, so it runs in `web-checks`) refuses any `*.spec.ts` that routes without `test.use({ serviceWorkers: 'block' })`; (2) the one-line spec change in C3-10, raised as a TCR row (`test-change-requests.md`), committed only after the senior-qa-engineer decides it. No skip, no WebKit exclusion, no product change | Every other spec that routes already blocks (`git grep -l '\.route(' origin/sprint-03 -- 'web/e2e/*.spec.ts'` → 13 spec files, 12 with `serviceWorkers: 'block'`; the 13th is `fe-minors.spec.ts`). The guard over the `sprint-03` E2E tree (`git archive origin/sprint-03 web/e2e`) → `[{"file":"sprint-03/fe-minors.spec.ts","line":28}]`, over `main` → `[]` | A guard turns the 12-times-repeated manual rule (TCR 2026-10-05 PD-S2R1-05 and others) into a check in the fast job, so the next spec cannot fail only in WebKit, only on CI (WebKit does not run in the sandbox). Alternatives: `serviceWorkers: 'block'` in `playwright.config.ts` for all projects would stop `security-headers.spec.ts` and the offline specs from testing the worker; a product change (no `fetch` handler, or static routes) would drop the offline page (A-05), and WebKit has no static routing API (judgment) |
