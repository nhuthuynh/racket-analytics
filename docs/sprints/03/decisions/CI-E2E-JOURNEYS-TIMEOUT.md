# CI-E2E-JOURNEYS-TIMEOUT decisions

Small decisions for ticket CI-E2E-JOURNEYS-TIMEOUT: main run 38016581726 (push, `0c5d513`, merge of ST-051-API / PR #53), job 114108085489. Its step "Playwright journeys; axe 0 serious/critical" ran from 02:23:06 to 03:05:24 and was cancelled at the job's 45 min limit, so `ci-gate` failed. One file per ticket (PO rule 2026-10-07).

## What the evidence shows

1. **Not a code regression: the same tree passed in 18.2 min.** The PR run of #53 (run 38012893964, job 114096740907) tested the merge commit `a89751c` ("Merge bf02c61 into 049aff2"). `git rev-parse a89751c^{tree} 0c5d513^{tree}` gives `5ff8147f67b270a05499fb948d178c49a8d8af7d` twice. That run: `Running 258 tests using 1 worker` ... `239 passed (18.2m)`, 19 skipped. Main at `049aff2` (run 38011153533, job 114097013319): `239 passed (19.2m)`. Run 37918385248: the step took 17.1 min.
2. **No test hung or failed; every test ran slower by about the same factor.** The `github` reporter prints one character per test, 80 per log line. Same 258 tests, same order:

   | Tests | PR run 38012893964 (centralus) | Main run 38016581726 (eastus) | Ratio |
   |---|---|---|---|
   | 1-80 | 01:25:02 -> 01:30:05 (5:03) | 02:23:08 -> 02:34:09 (11:01) | 2.18 |
   | 81-160 | -> 01:36:16 (6:11) | -> 02:51:33 (17:24) | 2.82 |
   | 161-240 | -> 01:42:11 (5:55) | -> 03:03:30 (11:57) | 2.02 |
   | 241-258 | -> 01:43:14 (1:03) | cancelled at 03:05:24, 18 tests left | |

   Every completed test passed (green dots, a few skipped); none reached its 60 s per-test timeout. A hang in one spec, a waiting magic-link or mailpit step, or a test-isolation stall would show as a long gap and a failure in one block, not as an even 2-2.8x slowdown of all three blocks (Chromium in blocks 1-2, WebKit in block 3).
3. **ST-051-API's `DELETE /me` cannot touch the gated run.** Only `e2e/sprint-03/delete-account.spec.ts` (and the `full-tag` / `journey-v2` specs) call deletion, and all three are tagged `@red-until-…`, so `--grep-invert "@red-until-"` leaves them out; they run in the next step, after the gated run. `grep -rln "/api/me\|Delete my account\|DELETE" web/e2e` -> `full-tag.spec.ts`, `delete-account.spec.ts`. The purge service runs at start and then every 86,400 s (`PURGE_INTERVAL_S`), and its new account work finds no deleted account during the gated run.
4. **Same image, different host.** Both jobs ran runner image `ubuntu-24.04` `20261004.327.1`. The only difference in the job logs before the tests (`diff` of both logs with timestamps removed) is the worker id and the region: `Region: eastus` (main) versus `Region: centralus` (PR run and 049aff2 run). The other jobs of run 38016581726 ran at their usual speed (stack start 1:32, integration object-store floor 4 s before and after the suites, backend suites 2:44). So the cause is the E2E runner of that one job: it ran the whole suite about 2.3 times slower.
5. **Why that cancelled the job.** The job ran both browsers one after the other on one worker (`test_the_gated_e2e_step_keeps_the_single_ci_worker`): a ~4.5 min setup, an 18-19 min gated step (growing: 17.1, 18.2, 19.2 min in the last runs) and an 8-10 min listed red-until step, about 31 min of a 45 min limit. A runner 1.5 times slower than usual was enough to cross it. Nothing bounded the gated run below the job limit, so the step ran until GitHub killed the job. The HTML report is only written at the end of a run, and "Service logs" ran on `failure()` only, so the cancel left nothing: `No files were found with the provided path: web/playwright-report/` and no service logs, no per-test durations and no runner facts.
6. **Local reproduction at `0c5d513` (Chromium, full HTTPS stack).** `docker compose -p e2etimeout -f infra/compose.yaml -f <build-secret override> --env-file infra/env.example up -d --build --wait` (with `DOCKERHUB_REGISTRY=mirror.gcr.io AUTH_LINK_LIMIT_PER_IP=1000 AUTH_EXCHANGE_LIMIT_PER_IP=1000`), then `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers PW_PROJECTS=chromium BASE_URL=https://localhost:3000 pnpm exec playwright test --grep-invert "@red-until-" --workers=1 --reporter=list,json` -> `119 passed (9.9m)`, 6 skipped, 4 failed: `rally-video.spec.ts:34`, `sprint-02/timing.spec.ts:222`, `sprint-03/timing.spec.ts:69` and `keyboard-and-narrow.spec.ts:12` (`locator('video')` not found). All four need an H.264 decoder: CI's Chromium leg runs Google Chrome (`e2e/helpers/browser-channel.ts`), the sandbox only has Playwright's bundled Chromium, and they pass on CI at this tree. The sum of the test durations was 586 s of 595 s wall time, so no time goes between tests. The slowest files: `evidence-crawl-harness.spec.ts` 85 s, `resumable-upload.spec.ts` 56 s, `upload-recovery.spec.ts` 52 s. WebKit is not installed in the sandbox, so its leg is measured on CI.

| 2026-10-10 | senior-frontend-engineer | **Root cause: the E2E job had no headroom and no bound.** Both browsers ran serially in one job using about 31 of its 45 min, so a runner about 2.3x slower (run 38016581726, eastus) ran the gated step past the job limit, and the cancel kept no report.
