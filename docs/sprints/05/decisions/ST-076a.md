| 2026-11-05 | sre-devops-engineer | **The dev store key of the backup has Read, List and Write on the media bucket**, not Read and List only (ADR 0058 rule 2, T5-BK-3) | SeaweedFS 3.97 `weed/s3api/auth_signature_v4.go` `reqSignatureV4Verify`: `identity.canDo(s3_constants.ACTION_WRITE, bucket, object)` for every SigV4 request. Probe on a Compose objectstore: `Read:racket-media,List:racket-media` → `AccessDenied` on ListObjectsV2 and GetObject; with `Write:racket-media` added → list 1, get ok | A read-only identity cannot exist in the dev store. Mitigations: the backup only sends `GET` (`test_the_mirror_only_reads_and_follows_every_listing_page`), the key reaches no other bucket and cannot create one (IT `test_backup_store_key_reaches_the_media_bucket_only`), and the production key is read-only (deployment item, ADR 0034). **Open: security-privacy-engineer** accepts this dev-only deviation from T5-BK-3 or asks for a store change |
| 2026-11-05 | sre-devops-engineer | **The scheduled service keeps running when a run is refused** (no recipient → `backup.run` `failed` at ERROR every slot); `--once` exits 2 | `test_no_recipient_exits_2_writes_nothing_and_still_prunes`; `test_failing_nightly_runs_keep_the_last_complete_set_until_stalled_fires` | ADR 0058 rule 2 (prune first on every run; the review round 2, F5 case). An exiting container under `restart: unless-stopped` would loop and never reach the next slot's prune |
| 2026-11-05 | sre-devops-engineer | **The service runs as the image's root user with every capability dropped**, read-only root, `/tmp` tmpfs, `no-new-privileges` | `test_backup_is_in_the_ops_profile_only_and_hardened` | The host directory `.local/backups` is created by Docker (root) when missing; a fixed non-root uid would not be able to write it. The IT runs the service as the test's own uid (`-u`) so the runner can read and delete what it wrote |
| 2026-11-05 | sre-devops-engineer | **Healthcheck = `backup.py --status`** (healthy while the newest complete set is ≤ 24 h old; 1 h start period) | `infra/compose.yaml` `backup.healthcheck` | The same freshness rule as NFR-045.1, so `docker compose ps` shows a missing recipient or failing runs as unhealthy |
