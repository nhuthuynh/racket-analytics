## Decisions

| Date | Who | Decision | Evidence | Why |

| 2026-11-05 | senior-backend-engineer | **"Confirmed corrections" = every committed row of `match_corrections` whose match is live (`matches.deleted_at IS NULL`), every column.** No filter on kind or undo. Revised in review round 1 (PR #209 F1): the first version also counted tombstoned matches | `backend/src/racket/matches/scorebook/integrity.py` (`sa.select(match_corrections).where(match_id IN live matches)`); unit `test_any_changed_column_changes_the_digest` (12 columns); IT-05-04 `test_it_05_04_a_tombstoned_matchs_corrections_are_not_counted`, `…restore_then_purge_of_a_backup_with_a_tombstoned_match_stays_equal`; scenario "A backup that holds a deleted match stays equal after restore and purge" (red at `1e4a9018`) | The trail is append-only by trigger (migrations 0010, 0011; ADR 0058 context 3), so a committed row is confirmed. All columns, read from the table, so a column added later is covered without editing this module. ADR 0058 rule 4 runs the purge (step 9) before `racket-integrity` (step 10) and the purge cascades a tombstoned match's trail, so counting those rows made every correct restore of a backup with a deleted match report `equal: false` (reviewer's probe: `(6, ff7af38f…)` vs `(3, 9632acc0…)`). A deleted match's corrections are no longer confirmed corrections the player can see (deletion-and-purge §3.1) |
| 2026-11-05 | senior-backend-engineer | **Canonical form: one JSON line per row (sorted keys, no spaces, ids as text, timestamps converted to UTC ISO 8601), SHA-256 over the lines in the order `(match_id, version, id)`, each line ending in `\n`.** Empty table → `(0, e3b0c442…b855)` (SHA-256 of no bytes). A timestamp without a time zone is refused | unit `test_one_row_hashes_its_canonical_json_line`, `test_rows_are_ordered_by_match_then_version_then_id`, `test_order_of_the_input_rows_does_not_change_the_fingerprint`, `test_same_instant_in_another_time_zone_is_the_same_row`, `test_key_order_inside_json_values_does_not_change_the_digest`, `test_empty_table_is_count_zero_and_the_digest_of_no_bytes` | The order is sorted in Python, not taken from the query, so the digest does not depend on the server's plan or collation. `id` breaks any tie within a version. JSONB key order is not stable across dump and restore, but sorted keys are |
| 2026-11-05 | senior-backend-engineer | **One export through the port:** `racket.matches.public` imports `corrections_fingerprint` and lists it in `__all__`. The check reads the source with `ast`, because importing the CLI also loads the port, and the port imports the scorebook itself |
| 2026-11-05 | senior-backend-engineer | **CLI contract for ST-076c:** `racket-integrity` prints `{"corrections": {"count": N, "sha256": "…"}}`; with `--expect-count N --expect-sha256 HEX` it adds `"equal"` and exits 1 on a mismatch, naming `corrections` on stderr. Exit 2 means a usage or configuration error (one expectation without the other, a non-integer count, a hash that is not 64 lower-case hex digits, no `DATABASE_URL`) or a database error. It reads `DATABASE_URL` only, not the full `Settings` | IT-05-04 `test_it_05_04_cli_*`; unit `test_usage_errors_exit_2`, `test_missing_database_url_exits_2` | The drill compares the value with `backup.json.corrections` (ADR 0058 rule 4 step 10). The restore step runs before the full app config exists, so needing S3 or auth settings would fail the check for an unrelated reason |
