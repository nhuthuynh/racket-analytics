## Addendum — Port the product to Go (PO decision 2026-10-06)

| Item | Decision |
|---|---|
| Scope | **Everything to Go**: API, domain (scoring, matches, identity, video ingest), job queue, workers (including the media probe and all future computer-vision inference, via ONNX Runtime / GoCV-style bindings). Supersedes the language part of ADR 0008. Offline model training/research tooling is not product code and may stay in Python if needed (to be decided in the port ADR with evidence). |
| Timing | **Sprint 6, directly after the R1 release candidate (Sprint 5), before any computer-vision work.** Release 2 (CV) shifts by one sprint: old S6–S9 become S7–S10. The sprint chain continues through Sprint 10. |
| Definition of done for the port | Behaviour parity proven by the language-independent tests: every Gherkin scenario, API integration test (rewritten to call HTTP, not Python internals, where needed), Playwright E2E and live goal-scorecard journey passes against the Go backend; Go unit tests replace Python unit tests at equal or better changed-line coverage; same security controls (ASVS L2, BOLA matrix, HTTPS dev stack, `__Host-` cookie). If parity cannot be reached in one sprint, the plan must say so up front and split it (strangler pattern), never ship a half-ported main. |

### Clarification (PO, 2026-10-06): no Python exception

**Everything in Go, including offline model training, dataset and research tooling, fixture generators, measurement scripts and CI helper scripts.** No Python in the repository's product, tooling or tests after the port. Where Go has no mature equivalent (e.g. model training), the team proposes a Go option (e.g. GoMLX/XLA, Gorgonia, or Go bindings to libtorch/ONNX Runtime) in an ADR with evidence and risks; it does not fall back to Python without a new PO decision.
