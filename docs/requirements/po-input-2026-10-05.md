### Clarification (PO, 2026-10-06): no Python exception

**Everything in Go, including offline model training, dataset and research tooling, fixture generators, measurement scripts and CI helper scripts.** No Python in the repository's product, tooling or tests after the port. Where Go has no mature equivalent (e.g. model training), the team proposes a Go option (e.g. GoMLX/XLA, Gorgonia, or Go bindings to libtorch/ONNX Runtime) in an ADR with evidence and risks; it does not fall back to Python without a new PO decision.

## Addendum — Ticket-level PRs and reviews (PO decision 2026-10-07)

PO: "each ticket in a sprint needs to have a PR, and each PR needs to be reviewed by principal and senior engineers before merge and tested scenarios with integration and unit tests, and the ticket needs to be developed using TDD and DDD".

| Rule | Detail |
|---|---|
| One PR per ticket | Every ticket (story, carry-over fix, goal-metric fix, plan and retro docs) is its own branch and PR into `main`. No sprint-wide integration branch. Tickets are sized for one reviewable PR (aim < 400 changed lines). |
| Reviews before merge | Each PR is reviewed by the **principal-engineer** and a **senior engineer** (a different senior role from the author where possible). Reviews are posted on the PR as GitHub reviews whose body starts "Verdict: APPROVE" or "Verdict: CHANGES REQUESTED". Merge only when both latest verdicts approve the current head SHA. Note: all agents post as the same GitHub account, which GitHub does not allow to formally *approve* its own PR, so the verdict lives in the review text; a branch-protection "required approvals" rule cannot be satisfied by the agents. |
| Tests in every PR | Gherkin scenario(s) + integration test(s) + unit tests for the ticket's behaviour, plus all CI jobs green incl. `ci-gate`. |
| TDD + DDD | Tests first and seen failing (negative case first), commit history shows tests before implementation; bounded contexts and ubiquitous language respected; domain layer free of frameworks. Reviewers check this explicitly. |
| Effective from | **Sprint 4.** Sprint 3 was already built on one branch when this rule arrived; it ships as one sprint PR, whose stories were each reviewed in the sprint review rounds. |
